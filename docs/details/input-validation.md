# 入力チェック仕様

[← 要件定義書に戻る](../requirements.md)

現行のDTO/Controller/ServiceとReactフォームに基づく。ブラウザ上の制約とサーバー検証は別々に記載する。
エラーメッセージの詳細は [error-messages.md](error-messages.md) を参照。

## ログイン・登録

| 入力 | サーバー側の制約・文言 |
| --- | --- |
| ログインメール | NotBlank「メールアドレスは必須です」、Email「正しいメールアドレスを入力してください」 |
| ログインパスワード | NotBlank「パスワードは必須です」。登録用の長さ・英数字制約は適用しない |
| 登録メール | 上記と同じ。重複は409「このメールアドレスは既に使用されています」 |
| ユーザー名 | 必須、3〜50文字、`^[a-zA-Z0-9_]+$`、重複不可。「ユーザー名は必須です」「ユーザー名は3〜50文字で入力してください」「ユーザー名は英数字とアンダースコアのみ使用できます」 |
| 表示名 | 必須、50文字以内、重複不可。「表示名は必須です」「表示名は50文字以内で入力してください」 |
| パスワード | 必須、8〜64文字、英字と数字を両方含む。「パスワードは必須です」「パスワードは8〜64文字で入力してください」「パスワードは英字と数字を両方含めてください」 |
| 読み仮名 | 任意、100文字以内。「読み仮名は100文字以内で入力してください」 |

UIではメール形式・必須をHTMLの制約でも検証する。確認パスワードはUIだけの項目で、
不一致なら「パスワードが一致しません」と表示し登録APIを呼ばない。読み仮名の文字種制約はない。
Emailアノテーションの挙動を、完全なRFC 5322検証を保証するものとは扱わない。

## 投稿・コメント

| 入力 | UI | サーバー |
| --- | --- | --- |
| 投稿本文 | 最大280文字、trim後に空なら送信不可 | NotBlank「投稿内容は必須です」、Size(max=280)「投稿は280文字以内で入力してください」 |
| 投稿画像 | JPEG/PNG/GIF、5MiB以内、選択時にプレビュー | 申告されたMIMEタイプとサイズを検証。「画像はJPEG・PNG・GIF形式、5MB以内でアップロードしてください」 |
| コメント | 最大280文字、trim後に空なら送信不可 | NotBlank「コメント内容は必須です」、Size(max=280)「コメントは280文字以内で入力してください」 |

画像の5MBは実装上 `5 * 1024 * 1024` bytes。画像デコードや内容の真正性検証を行う仕様ではない。
multipartリクエスト自体の上限もSpring設定で5MB。

## プロフィール編集

| 入力 | UI | サーバーの現状 |
| --- | --- | --- |
| 表示名 | maxLength=50、trim後に空なら保存不可 | displayNameパラメータ必須。文字列用Bean Validationは未接続。DBにNOT NULL・VARCHAR(50)・UNIQUE制約 |
| 自己紹介 | maxLength=160 | bioは任意パラメータ。文字列用Bean Validationは未接続。DBはVARCHAR(160) |
| アバター | JPEG/PNGをファイル選択で指定、5MiB超でエラー | MIMEタイプJPEG/PNGと5MiB以内を検証。「画像は JPEG・PNG 形式、5MB以内でアップロードしてください」 |

`UpdateProfileRequest` は存在するが現行更新Controllerは使用していない。UIを迂回した文字列入力に
専用の400エラーが返るとは限らず、DB制約違反は汎用500になる場合がある。これは機能修正の対象外で、現状の制約。

## ユーザー検索

UIはtrim後に空ならAPIを呼ばず、1文字以上の入力から300msで検索する。
APIはq必須、空白のみなら400「検索キーワードを入力してください」。page既定0、size既定20。
現行APIにはpage/sizeの範囲検証はない。半角・全角スペース除去と読み仮名側のひらがな化を行う。
